# stockhook_targets.txt
# The Dwarf Fortress builds Stockhook's DLL may hook. Goes in the mod's
# root folder, beside dfhooks_stockhook.dll; the installer copies both into
# DF's folder, and the DLL reads this file there at launch.
#
# WHY: the hook assumes things about one DF build: where its stockpile
# check is, which bytes start it, and where four of the item's methods sit
# in its vtable. A DF update can change any of them, so a build is named by
# the exe's PE timestamp and hooked only when it is either LISTED here (or
# built into the DLL), or VERIFIED: for a build not listed, the DLL checks
# at launch that the reference signatures are found exactly once, that the
# item vtable read through DF's own RTTI is where the hook expects, and
# that the check still calls the material slots (stockhook_dll.cpp, THE
# AUTOMATIC TARGET). A build that is neither is left alone: stockpiles then
# work exactly as DF's own, RM's fallback runs, and RM's prompt says so at
# the fort load.
#
# WHEN TO ADD A LINE: only when the automatic checks refuse a build (its
# reason is the last NOT HOOKING line in stockhook.log), or to skip the
# checks: a verified build writes its own line into stockhook.log, ready
# to paste here. A line here is the whole fix: no recompile.
#
# FORMAT, one build per line, numbers in hex, # starts a comment:
#   build <PE timestamp> rva <function RVA> stolen <bytes the jump replaces>
#   vt <getType> <getSubtype> <getMaterial> <getMaterialIndex> sig <bytes>
# sig: the function's first bytes, ?? for any byte (never inside the stolen
# bytes, which are copied as found). If the function moved, it is found by
# a scan for sig, which must match exactly once. stockhook.log in DF's
# folder names the build of the running exe, and says why it did or did
# not hook.
#
# A line for a build the DLL already knows replaces the built-in values.
#
# THE COLOUR FUNCTION (optional, on the same line): crva, cstolen and csig
# name the function DF colours each settings category with (red, grey,
# green), the same way: where it is, how many bytes the jump replaces, its
# first bytes. Hooked, it counts Stockhook's rows in a category's colour.
# A line without them hooks the stockpile check alone; for a build the DLL
# knows, its built-in colour target is used.
